# 페르소나 분석용 테스트 모드 (DEV 전용)

결제·GPT 호출·실제 데이터 없이, 구독자/구매자 화면(운세 전체 탭, 심층 리포트, 2027 신년 리포트)을
모바일 웹 미리보기에서 볼 수 있게 하는 모드입니다. 릴리스/OTA 번들에는 들어가지 않습니다.

## 켜는 법

```bash
cd mobile && npx expo start --web --port 8082
```

브라우저(모바일 뷰포트 375x812 권장)에서 아래 URL을 엽니다.

| 파라미터 | 값 | 의미 |
| --- | --- | --- |
| `qa` | `free` / `pro` / `all` / `off` | 무료 / 구독자 / 구독자 + 모든 리포트 구매. `off`로 끄기. 한 번 켜면 localStorage에 기억 |
| `persona` | 아래 표의 키 | 사주 결과·닉네임·언어·관심사가 미리 채워진 사용자 |
| `lang` | `ko` / `en` / `es` | 언어만 덮어쓰기 (선택) |

예: `http://localhost:8082/?qa=all&persona=mia`

## 페르소나

| 키 | 닉네임 | 언어 | 관심사 | 성격/관점 |
| --- | --- | --- | --- | --- |
| `mia` | Mia | en | 관계 | Co-Star류 점성술 앱 헤비유저. 톤·신뢰·공유 가치를 봄 |
| `lucia` | Lucía | es | 관계 | 스페인어권. 번역투/어색한 문장에 민감 |
| `jisoo` | 지수 | ko | 자기·일상 | 사주에 익숙한 한국어 사용자. 용어·정확성 |
| `jordan` | Jordan | en | 자기·일상 | 사주 처음. 용어 설명이 없으면 이탈 |
| `sam` | Sam | en | 자기·일상 | 접근성(글자 크기·대비·터치 영역·스크린리더) 관점 |
| `riley` | Riley | en | 관계 | 스트레스 테스트: 뒤로가기·연타·중단·재진입 |
| `casey` | Casey | es | 자기·일상 | 산만한 사용자. 3초 안에 가치가 안 보이면 나감 |

## 볼 수 있는 것

- 홈의 점선 QA 패널 → "Open sample deep report": 실제 GPT가 쓴 40쪽 심층 리포트 (ko/en/es).
  `qa=free`/`pro`는 14쪽에서 페이월, `qa=all`은 전체.
- 홈의 신년 리포트 행 → 2027 신년 리포트 (구매 처리된 것으로 보이고, 저장된 결과가 바로 열림).
- 운세: 구독자는 봉인된 히어로를 탭하면 그날 전체 운세가 바로 열림.
- 리포트 이름은 페르소나 닉네임으로 치환됩니다.

## 규칙

1. 실제 결제·구매 복원·로그인은 시도하지 않는다. 서버는 여전히 자체적으로 구매를 검증하므로
   이 모드로는 유료 콘텐츠를 서버에서 받을 수 없다.
2. 프로덕션 API에 새 데이터를 쓰지 않는다 (샘플 사주는 sessionId 없이 계산해 저장하지 않음).
3. QA 데이터(`qaData.ts`)는 `__DEV__` 안에서만 `require`한다. 릴리스 번들에서 빠지는지는 아래로 확인.

## 프로덕션 번들 제외 확인

```bash
cd mobile && npx expo export --platform ios --output-dir /tmp/qa-export && grep -rl "Bright Output, Hidden Burnout" /tmp/qa-export || echo "OK: fixture not in bundle"
```

## 페르소나 서브에이전트 프롬프트 템플릿

> 너는 Fatesaid 앱의 사용자 "{닉네임}"({성격/관점})이다. 브라우저 탭에서
> `http://localhost:8082/?qa={free|pro|all}&persona={키}`를 열고, 375x812 모바일 뷰포트로 실제 사용자처럼
> 홈 → 운세 → 리포트 → 신년 리포트 → 공유 카드를 순서대로 써 본다. 결제/로그인은 시도하지 않는다.
> 각 화면에서 (1) 첫 3초에 이해되는가 (2) 문구가 어색하거나 불안을 주는가 (3) 결제 의향이 생기는 지점과
> 막히는 지점 (4) 이탈하고 싶어진 순간을 기록하고, 마지막에 화면별 점수(1~5)와 가장 고치고 싶은 3가지를
> 근거(화면·문구 인용)와 함께 보고한다. 코드는 수정하지 않는다.
