_작성: 2026-10-06. 제미나이는 조사와 초안만 맡는다. 코드 반영, 광고 집행, 배포는 하지 않는다._

## 0. 준비 (한 번만)

1. 제미나이에서 **Gem**을 하나 만든다. 이름은 "Fatesaid 마케팅"으로 한다.
2. Gem의 **지침** 칸에 아래 1장의 "공통 지침" 코드 블록을 그대로 붙여 넣는다.
3. Gem의 **지식** 파일로 `APP_OVERVIEW.md`를 올린다. 여유가 있으면 `PRODUCT.md`도 올린다.
4. 대화는 두 갈래로 나눈다. **SEO 대화 하나, 메타 광고 대화 하나**로 하면 맥락이 섞이지 않는다.
5. 한 메시지에 한 단계만 시킨다. 결과가 마음에 들면 아래 경로로 저장한 뒤 다음 단계로 넘어간다.

| 결과물 | 저장 위치 |
|---|---|
| SEO 키워드 표 | `marketing/seo/01-keywords.md` |
| SEO 사이트 구조·글 목록 | `marketing/seo/02-site-plan.md` |
| SEO 글 초안 | `marketing/seo/articles/<slug>.en.md`, `.es.md` |
| 메타 경쟁 조사 | `marketing/meta/01-competitors.md` |
| 메타 전략·타깃 | `marketing/meta/02-plan.md` |
| 메타 훅·카피 | `marketing/meta/03-hooks.md` |
| 메타 릴스 대본 | `marketing/meta/04-scripts.md` |

저장한 뒤 Claude에게 "marketing/ 검토하고 반영해 줘"라고 하면 Claude가 규칙 위반과 사실 오류를 확인하고 실제 페이지로 옮긴다.

### 결과 가져오기

단계가 끝날 때마다 아래 명령을 붙여 넣는다. 첫 줄의 파일 경로만 위 표에 맞게 바꾼다.

````
방금 결과를 파일로 저장할 거야. 아래 형식으로 다시 출력해 줘.

- 전체를 마크다운 코드 블록 하나(```markdown … ```)에 담아 줘.
- 첫 줄은 파일 경로 주석: <!-- marketing/seo/01-keywords.md -->
- 그 아래 제목, 작성일(오늘 날짜), 한 줄 요약.
- 본문은 표와 목록 그대로. 설명이나 인사말은 코드 블록 밖에도 쓰지 마.
- 추정한 수치와 확인 못 한 내용은 "(추정)", "(미확인)"으로 표시해.
- 맨 끝에 "## 규칙 점검" 섹션: 공통 지침 1~10 중 어긴 게 있는지 한 줄씩.
- 길어서 잘리면 "1/2", "2/2"로 나눠서 코드 블록 두 개로 줘.
````

가져오는 방법은 둘 중 편한 쪽을 쓴다.
1. **Claude 채팅에 그대로 붙여 넣기(가장 쉬움).** Claude가 첫 줄 경로대로 파일을 저장하고 바로 검토한다. 여러 단계를 한 번에 붙여 넣어도 된다.
2. 코드 블록을 복사해 해당 경로에 직접 저장한 뒤 Claude에게 "marketing/ 검토해 줘"라고 한다.

- 표가 깨졌으면 "표 형식이 깨졌어, 같은 내용을 마크다운 표 문법으로만 다시 줘"라고 한 번 더 시킨다.
- "Google Docs로 내보내기"는 표가 깨지기 쉬우니 쓰지 않는다.

## 1. 공통 지침 (Gem 지침 칸에 붙여 넣기)

```
너는 Fatesaid의 그로스 마케터야. 첨부한 APP_OVERVIEW.md가 제품 설명이니 항상 먼저 참고해.

[제품 요약]
- Fatesaid: 한국 사주(Four Pillars)를 천문 데이터로 실제 계산하고, 심리검사·AI 상담과 엮어 자기이해를 돕는 모바일 앱(iOS·Android).
- 타깃: 영어·스페인어권 20~30대, Co-Star·The Pattern 같은 점성술/성격 앱 사용자. 한국어는 부차적.
- 웹 fatesaidapp.com은 광고·검색 유입용이다. 웹에서 할 수 있는 건: 생년월일만으로 무료 사주 유형 카드, 무료 사주 계산기(/saju-calculator), Q&A 맛보기. 웹에는 결제와 로그인이 없다. 모든 CTA는 "무료로 내 차트 보기" 또는 "앱 받기"로 끝난다.
- 앱은 아직 정식 출시 전이다(스토어 심사·비공개 테스트 중).

[절대 규칙]
1. 후기, 사용자 수, 다운로드 수, 언론 보도, 평점, "정확도 N%" 같은 수치를 지어내지 마. 아직 그런 데이터는 하나도 없다.
2. 불운한 날, 나쁜 궁합, 건강·질병·사고·죽음·재난 예언, "돈을 잃는다" 같은 단정적 부정 예언을 쓰지 마. 대신 "속도를 늦출 날"처럼 리듬으로 표현해.
3. 가짜 긴박감(카운트다운, "오늘만", "곧 마감")과 공포 마케팅을 쓰지 마. 가벼운 호기심은 괜찮아.
4. 보는 사람의 성격·정신건강·연애 상태·외모 등 개인 특성을 짐작하는 2인칭 문구를 쓰지 마. 예: "Are you an anxious attacher?", "Feeling burned out?" 이건 Meta 개인 특성 광고 정책 위반이다.
5. 점술·진단·치료가 아니라 자기이해 도구라고 표현해. 의료·심리치료 효과를 약속하지 마.
6. 사주 용어는 한자나 직역 대신 쉬운 영어·스페인어로 풀어 써. 예: 일간 → "your Day Master, the element that represents you".
7. 스페인어는 번역투가 아니라 원어민이 쓴 것처럼 써. 독자를 tú로 부르고, 성별을 짐작하지 마.
8. 강점으로 내세울 사실: 실제 천문 데이터 기반 계산, 출생 도시 경도로 시간 보정, 50가지 사주 유형, 심리검사와 AI 대화를 함께 쓰는 리포트, 영어·스페인어·한국어 지원.
9. 모르는 수치(검색량, CPM 등)는 "추정"이라고 표시하고, 근거나 출처를 함께 적어.
10. 결과는 마크다운 표나 목록으로 줘. 내가 파일로 저장할 거야.
```

## 2. 웹 SEO

### 지금 웹에 있는 것 (제미나이에게 알려 줄 사실)
- 페이지: `/`(랜딩 + 유형 카드), `/saju-calculator`(무료 계산기: 네 기둥, 일간, 오행 분포), `/privacy`, `/terms`, `/data-deletion`. `/c/<code>`는 친구 궁합 초대용이라 검색에서 제외한다.
- 언어는 `?lang=en|es|ko`로 바뀌고, 언어별 canonical과 hreflang이 있다. OG 이미지가 있다.
- **없는 것**: sitemap, robots, 설명 글(블로그), 유형별 페이지.

### 1단계: 키워드 조사

```
SEO 1단계만 해 줘. 영어와 스페인어 키워드를 조사하는 단계야.

- 주제: saju, Four Pillars of Destiny, Korean astrology, day master, five elements(오행), 사주 궁합(compatibility), birth chart calculator, 그리고 "Korean zodiac"처럼 헷갈리기 쉬운 주변 키워드까지.
- 실제 검색 결과를 보고 언어별로 30개씩 골라 줘.
- 표 형식: 키워드 | 언어 | 검색 의도(정보/도구/비교) | 경쟁 정도(상중하, 추정) | 지금 상위에 있는 사이트 유형 | 맞는 페이지 종류(계산기/설명 글/유형 페이지/랜딩)
- 마지막에 "작은 사이트가 이길 수 있는 틈새" 키워드 10개를 따로 뽑고 이유를 한 줄씩 적어 줘.
```

### 2단계: 사이트 구조와 글 목록

```
SEO 2단계. 1단계 결과(아래 붙임)를 바탕으로 fatesaidapp.com에 추가할 페이지 계획을 짜 줘.

[1단계 결과 붙여넣기]

- 페이지 종류 후보: 설명 글(what is saju 등), 일간 10종 페이지(예: "Yang Wood Day Master"), 오행 5종 페이지, 계산기 보강, 비교 글(saju vs western astrology).
- 표 형식: 우선순위 | URL slug | 대상 키워드(주·보조) | 언어 | 페이지 목적 | 내부 링크(어디로 보내나: 계산기/유형 카드/앱)
- 우선 만들 10개를 고르고 이유를 적어 줘.
- 영어와 스페인어를 같은 URL에서 ?lang=으로 나눌지, 언어별로 다른 slug를 쓸지 장단점도 적어 줘.
- 각 페이지의 title(60자 이내)과 meta description(155자 이내)을 영어·스페인어로 써 줘.
```

### 3단계: 글 초안 (한 번에 하나)

```
SEO 3단계. 2단계 목록의 [slug] 글을 영어로 먼저 써 줘.

- 1,000~1,500단어, H2/H3 구조, 첫 문단에서 검색 의도에 바로 답하기.
- 사실은 사주 일반 지식과 APP_OVERVIEW에 있는 것만 써. 확실하지 않은 역사나 통계는 빼.
- 본문 중간 한 번, 끝에 한 번 CTA: 무료 계산기(/saju-calculator) 또는 무료 유형 카드(/)로.
- 끝에 FAQ 3~5개(구조화 데이터용 Q/A 형식).
- 마지막에 "규칙 점검" 목록: 공통 지침 1~7을 하나씩 확인한 결과를 적어 줘.
```

영어 초안이 괜찮으면 "같은 글을 스페인어 원어민 독자용으로 다시 써 줘(번역 말고 재작성)"라고 이어서 시킨다.

## 3. 메타 광고 기획

### 전제 (제미나이에게 알려 줄 사실)
- 아직 앱 출시 전이므로 첫 목표는 **웹 랜딩의 무료 유형 카드로 보내 어떤 훅이 생년월일 입력까지 가는지 테스트**하는 것이다. 설치 캠페인은 출시한 뒤에 한다.
- 지금은 Meta Pixel도 Meta SDK도 없다. 측정 설계도 기획에 포함한다.
- 광고 소재로 쓸 수 있는 실제 화면: 사주 유형 공유 카드, 궁합 공유 카드, 9:16 영역 카드(돈, 설렘 등), 사주 원국 그래프, 리포트 페이지.
- 타깃 국가 후보: 미국, 멕시코, 스페인, 그 밖의 중남미. 스페인은 EU라 쿠키 동의가 필요하다.

### 1단계: 경쟁 광고 조사

```
메타 광고 1단계. Meta 광고 라이브러리 기준으로 Co-Star, The Pattern, Sanctuary, Nebula, CHANI 등 점성술·성격 앱 광고를 조사해 줘.
(직접 볼 수 없으면 공개 자료로 알 수 있는 범위만 쓰고, 그렇다고 표시해 줘.)

- 표 형식: 앱 | 광고 형식(릴스/이미지/캐러셀) | 훅 첫 문장 | 각도(호기심/정체성/궁합/공유욕/유머) | CTA | 눈에 띄는 점
- 공통 패턴 5개와 "우리가 따라 하면 안 되는 것"(공통 지침 위반)을 따로 정리해 줘.
- Fatesaid만 쓸 수 있는 차별 각도 3개를 제안해 줘(예: 한국 사주라는 낯섦, 실제 천문 계산, 공유하고 싶은 유형 카드).
```

### 2단계: 캠페인 전략

```
메타 광고 2단계. 출시 전 소액 테스트 계획을 짜 줘.

- 목표: 웹 랜딩에서 무료 유형 카드를 받는 사람 수(생년월일 입력 완료)를 전환으로 잡고, 어떤 훅·소재가 이기는지 찾기.
- 포함할 것: 캠페인 구조(캠페인/광고 세트/광고), 국가·언어 나누는 방법, 타깃(넓게 + 관심사 후보), 소재 테스트 설계(한 번에 바꿀 변수), 판단 기준 지표와 대략적인 기준값(추정이면 표시), 기간.
- 측정: Meta Pixel과 Conversions API로 어떤 이벤트를 보내야 하는지, UTM 이름 규칙, 스페인(EU) 쿠키 동의 때문에 생기는 영향.
- 출시 후 2단계: 앱 설치 캠페인으로 넘어갈 때 필요한 것(SDK 또는 MMP, iOS ATT/SKAdNetwork)을 체크리스트로.
- 예산은 내가 정할 거니까 "하루 예산 X일 때"처럼 변수로 써 줘.
```

### 3단계: 훅과 카피

```
메타 광고 3단계. 훅과 광고 문구를 만들어 줘.

- 영어 15개, 스페인어 15개.
- 표 형식: 훅(첫 문장) | 본문 1~2줄 | CTA 버튼 | 언어 | 각도 | 쓸 소재(유형 카드/궁합 카드/원국 그래프 등) | Meta 개인 특성 정책 위험(상중하 + 이유)
- 공통 지침 4번을 특히 지켜 줘. "당신은 ~하죠?" 대신 제품과 결과물을 주어로 써. (좋은 예: "Your birth date has a Korean saju type. Here's how to find yours.")
- 위험 '하'인 것 중 가장 강한 5개를 골라 이유를 적어 줘.
```

### 4단계: 릴스·스토리 대본

```
메타 광고 4단계. 3단계에서 고른 5개 훅으로 15초 릴스/스토리 대본을 써 줘.

- 형식: 초 단위 장면 | 화면(무엇을 보여 주나, 실제 앱·웹 화면만) | 자막 | 내레이션(선택)
- 흐름: 0~2초 훅 → 생년월일 입력 → 유형 카드 공개 → CTA.
- 가짜 후기, 가짜 알림 화면, 사람 얼굴 연출의 "리액션 영상"은 쓰지 마.
- 영어와 스페인어 각각.
```

## 4. 제미나이가 하지 않는 일 (사용자 또는 Claude가 맡음)

- 페이지 코드, sitemap/robots 추가, Pixel 설치, 쿠키 동의 배너, 이벤트 허용 목록 수정은 Claude가 SPEC으로 묶어서 한다.
- 광고 계정 생성, 결제 수단, 예산, 집행은 사용자가 한다.
- 개인정보처리방침 갱신(Pixel 도입 시 필수)은 Claude가 초안을 쓰고 사용자가 확정한다.
