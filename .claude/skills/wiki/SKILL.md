`WIKI.md`를 현재 코드와 맞춘다. 독자는 다음 세션의 나와 사용자다.

1. `WIKI.md`, `TODO.md`(있다면 `[x]` 항목), `git log -10 --stat`, 필요하면 `git diff`를 읽는다.
2. 구조나 흐름이 바뀐 곳만 갱신한다. 새 API 라우트, 데이터 흐름, 외부 서비스 연결, 배포 경로, 파일 위치가 대상이다.
3. 코드 조각은 넣지 않는다. 시스템의 큰 그림과 흐름을 파악할 수 있는 만큼만, 파일 경로를 포인터로 쓴다.
4. 코드나 실행으로 확인하지 못한 내용은 쓰지 않거나 `(미확인)`으로 표시한다. 지어내지 않는다.
5. 더는 사실이 아닌 문장은 고치거나 지운다.
6. 무엇을 바꿨는지 한두 줄로 보고한다.

`WIKI.md`에 넣지 않는 것: 진행 중인 작업(`TODO.md`), 프로젝트 전체 상태와 결정(`HANDOFF_*.md`), 제품 원칙(`PRODUCT.md`).
